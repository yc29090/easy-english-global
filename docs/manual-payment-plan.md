# 人工收款与 Gmail 订单提醒实施说明

状态：开发分支设计基线，**尚未上线、尚未启用收款或邮件发送**。

## 已确认的业务需求

- 产品：简单英语 Easy English Global。
- 商品：终身会员，固定人民币 99 元（9900 分）。
- 收款：个人微信／支付宝人工收款；**不得将用户点击“我已付款”视为到账**。
- 通知：Gmail 管理员邮箱 `sdqtyc@gmail.com`，不接入微信公众号。
- 管理：手机端管理员订单列表、人工核实到账、确认后开通终身会员。
- 成本：保留现有 Render Free 和 Neon Free；不得未经批准创建付费资源。

## 开发与安全验收清单

1. 新增独立的人工支付订单 API；保留生产环境禁止 mock checkout 的现有保护。
2. 登录用户可生成或查看本人未处理订单，金额和币种由服务器固定，不能由客户端更改。
3. 客户选择微信／支付宝，并在实际付款后提交“我已付款”；订单状态为 `payment_claimed`，而非 `paid`。
4. 管理员才能查看所有待审核订单；列表仅包含审核所需信息，不能向普通用户泄露其他人的订单。
5. 管理员核对真实收款账户后，使用受权限保护的接口确认收款；数据库事务内完成订单确认、会员升级和审计日志，重复提交必须幂等。
6. 拒绝未付款订单、错误用户、重复支付及对管理员自身的非法会员修改。
7. 订单通知采用异步／失败不丢单原则：邮件失败不得回滚订单，管理员后台始终可查看待审核记录；记录发送失败以供排查，不记录密钥。
8. 邮件发送使用现有 mail provider 体系；发送前必须配置合法发件人和服务商密钥，**Gmail 收件地址不等于 Gmail SMTP 凭据**。不得在代码库提交任何密码、密钥或收款二维码敏感信息。
9. 微信／支付宝收款码需要所有者提供**用于商业收款且符合平台规则**的合法收款信息后才能对外展示。付款说明必须提醒用户填写可核对的订单编号；不得仅凭截图自动放行。
10. 增加手机端订单审核界面与相关自动化测试；未通过权限、重复确认、邮件失败和生产环境检查前不得部署。
11. 生产只读检查已存在 1 个管理员；保留该账号，不得再次初始化。实际登录验收另行核实。
12. 真实上线前明确退款、争议、隐私和个人收款渠道适用性；未经用户确认不得开启真实收费。

## 既有系统约束

- 现有 `/api/orders` POST 和 `/api/orders/confirm` 仅用于非生产环境 mock checkout，不可直接打开生产模拟支付。
- 已有 `orders` 表、管理员角色、终身会员状态、审计日志、邮件模块，开发需复用并确保向后兼容。
- 本分支合并及部署均需要单独审核；Render 当前自动部署关闭。
